Como é Feito — Processo Técnico
SERE — Sistema Estadual de Registro Escolar
Gestão: SEED/PR
Tecnologia: PostgreSQL · banco escola · view seed.mv_pdm2_estudantes
Dados fornecidos: escolas (codmec/INEP), turmas, alunos (CPF, nascimento, filiação), matrículas, seriação para mapeamento de etapa SGP

Trabalho recente (02–03/09): sessão de correção de bugs de etapa de ensino e casamento de turma na enturmação — corrigido problema em que múltiplas linhas candidatas por aluno no SERE geravam erro de "instituição incompatível" ou "etapa 0".
RCDIGM — Registro de Classe Online
Gestão: Secretaria Municipal de Educação de Curitiba
Tecnologia: PostgreSQL · mirror de tb_matricula/tb_turma/tb_frequencia/tb_aula, view seed.mv_pdm2_frequencia_mensal
Dados fornecidos: frequência mensal (horas ofertadas/presença), disciplinas por turma (tb_classe) para o de-para de componentes curriculares

Limitação identificada: vínculo de componentes curriculares ainda não migrado para produção em escala.

Nota metodológica: os números de matrículas/estudantes/turmas/enturmação desta página vêm de um redownload completo do SGP feito ao vivo em 03/09/2026 às 09:42 (não de um log de envio). Já os indicadores de "status do envio" de frequência e componentes curriculares vêm da tabela de log local (envio_lotes/envio_payloads) — essa tabela historicamente não confirma o status final de todo lote (muitos ficam como "pendente" mesmo já processados no SGP), então "não verificado" acima significa apenas isso: sem confirmação local, não necessariamente "não enviado".
