1. O que é o NEXO?

O NEXO é um sistema desenvolvido pela SEED-PR para centralizar, validar e enviar automaticamente dados educacionais dos municípios paranaenses ao Sistema Gestão Presente (SGP) do Ministério da Educação. O envio desses dados é obrigatório e fundamenta políticas como o programa Pé-de-Meia.

O sistema funciona como uma ponte inteligente: de um lado, puxa os dados do banco oficial do estado (SERE); do outro, permite que o próprio município revise, corrija e complemente as informações que só ele possui — como quem são seus professores, quais turmas foram abertas e qual foi a frequência de cada aluno. Após validação, o NEXO envia tudo automaticamente ao MEC.

Mecanismo central (API 2.0): O município de Rede Municipal do Paraná assina um Termo de Autorização diretamente no SGP. Com isso, a SEED-PR passa a operar em nome do município — sem que a prefeitura precise gerenciar credenciais de API. A identificação do município (X-CODIGO-ENTIDADE) é inserida automaticamente em cada envio.

4. Fluxo do processo — 12 etapas
SEED / CODIS
Sistema NEXO
Rede Municipal do Paraná
Etapa 1

Extração do SERE

Script Python lê dados de SJP 2026 (alunos, matrículas, turmas, estabelecimentos) e carrega no banco de trabalho.

Etapa 2

Filtragem de elegibilidade

Sistema separa matrículas com etapa de ensino válida na API 2.0, descarta modalidades sem mapeamento e aplica regras do catálogo de exclusão.

Etapa 3

Abertura do ciclo de validação

SEED abre ciclo 2026 para SJP. Portal disponibiliza dados e modelos de planilha para download.

Etapa 4

Município acessa o NEXO

Gestor de SJP recebe credenciais de acesso e visualiza todos os alunos, turmas e matrículas pré-carregados do SERE.

Etapa 5

Preenchimento das planilhas

Município baixa e preenche: Profissionais, Turmas extras, Componentes Curriculares, Frequências (para escolas sem RCO) e Avaliação de Desempenho.

Etapa 6

Upload e revisão dos dados

Município faz upload das planilhas no NEXO e revisa/corrige dados de alunos carregados do SERE (CPF, nome, data de nascimento).

Etapa 7

Validação automática

NEXO valida CPF (dígito verificador), campos obrigatórios e domínios da API 2.0. Inconsistências aparecem em vermelho na tela do gestor.

Etapa 8

Correção das inconsistências

Município resolve os erros apontados. O sistema não avança para envio enquanto houver pendências críticas em aberto.

Etapa 9

Confirmação pelo município

Gestor confirma formalmente que os dados estão corretos e submete o ciclo para homologação da SEED.

Etapa 10

Homologação pela SEED

Analista da SEED revisa o pacote confirmado pelo município e libera para envio ao SGP.

Etapa 11

Envio à API CMDE 2.0

Scripts enviam em cascata: Escolas → Turmas → Comp. Curriculares → Estudantes + Matrículas → Profissionais → Frequências → Avaliações. Cabeçalho X-CODIGO-ENTIDADE identifica SJP.

Etapa 12

Monitoramento e log

NEXO exibe status de cada lote enviado. Erros são registrados e reprocessados. SEED confirma conclusão.

7. Pontos em aberto — definições necessárias na reunião
1
Autorização / API

SJP já assinou o Termo de Autorização no SGP?

Sem o termo, a SEED não pode enviar dados em nome do município. A janela de Escolas e Estudantes encerra em 08/05/2026 — 3 dias restantes. Quem aciona o município para assinar? É urgente.

2
Banco de dados

Qual será o nome e ambiente do banco de trabalho do NEXO?

Precisa ser definido o nome do banco SQL Server onde o NEXO armazenará os dados. Será um banco novo no ambiente existente ou um novo servidor?

3
Escopo / Dados

Quais e quantas escolas municipais de SJP entram no piloto?

Todas as escolas municipais? Apenas algumas? Há escolas privadas conveniadas? Qual é o total de alunos estimado para dimensionar o volume de envio?

4
Pessoas / Responsabilidade

Quem é o responsável técnico pelo lado do município?

Precisamos de nome, cargo, e-mail e telefone do gestor de SJP que irá operar o NEXO e preencher as planilhas. Quem faz o contato e define isso?

5
Frequência / RCO

Quais escolas de SJP usam o RCO? Qual o percentual?

Para escolas com RCO, a frequência é automática. Para as demais, o município preenche planilha manualmente. Precisamos mapear escola por escola.

6
Dados / Turmas

As turmas de SJP 2026 estão cadastradas no SERE?

Se sim, podem ser pré-carregadas. Se não, o município precisará preencher toda a planilha de turmas — aumentando significativamente o esforço inicial.

7
API / Prazo

A URL da API CMDE 2.0 já está disponível para homologação?

O último registro indica que a URL de homologação estava pendente. Precisamos confirmar a URL base e as credenciais para iniciar os testes.

8
Processo / Periodicidade

O envio ao SGP será mensal (contínuo) ou carga inicial única?

A API 2.0 exige frequências mensais. O NEXO precisa ser operado todo mês? Ou o foco é uma carga retroativa de 2026 e depois ativação de um processo mensal automático?

9
Matrículas / Regras

Revisar catálogo de exclusão para múltiplas matrículas na API 2.0

A API 2.0 aceita múltiplas matrículas ativas por aluno. O catálogo de exclusão precisa ser revisado: só excluir o que não tem etapa mapeável na API, não mais toda matrícula "complementar".
